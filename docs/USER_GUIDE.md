# FileAtlas 智能文件整理

Windows 11 桌面应用，使用系统 Acrylic 背景模糊与浅色半透明面板。支持多级分类、独立保存地址、本地 Claude Code 语义分类、自动标签、实时监控、可撤销归档和 Markdown 文件目录。

## 启动

打开发行目录中的 `FileAtlas.exe`。整个 `_internal` 文件夹必须与 EXE 一起保留。无需安装 Python。

1. 打开“分类与目录”，新建多级分类，为每个节点设置保存地址和分类依据；也可点击“从现有目录生成分类”读取已有文件夹结构。
2. 打开“自动化设置”，添加默认整理源，检查 `claude.exe` 的位置，然后保存。
3. 点击“扫描源文件夹”。首次使用默认进入“待审核”，可修改目标分类后整理。
4. 设置归档方式（复制或移动），启用“自动执行”，然后点击“启动自动监控”。高于置信度阈值的分类结果自动归档，其他结果保留在待审核。
5. “整理记录”可以撤销成功操作。“分类与目录”显示文件树，并可导出 Markdown 目录。

默认关闭窗口后继续在系统托盘运行。右键托盘图标选择“退出”。监控在点击启动后生效，重新打开程序时需要再次启动监控。

## Claude Code

需要已安装并配置的 Windows 原生 Claude Code（`claude.exe`），继承它当前的服务、认证与默认模型。应用不会更改全局 Claude 配置。可在应用设置中单独覆盖模型和模型服务地址。

首次启动时，如果 Claude 指向本地 Ollama，且原模型名称已不存在而服务中只有一个已安装模型，会将该模型保存为本应用的默认模型，并记录提示。检测只访问本机服务，不修改全局配置。

Claude 在本机以 `-p --output-format json` 启动，但模型运行位置取决于 Claude 的服务配置。使用云服务时，文件名、路径和启用后的内容摘录会发送到该服务；使用本地 Ollama 等兼容服务时则由本地服务处理。可关闭内容摘录，仅发送文件名与元数据。已有文件夹导入只按位置生成初始标签，不调用 AI。

分类调用禁用文件/命令工具、MCP、斜杠命令和 Hooks。AI 只返回分类 ID、标签和依据，文件操作由应用执行并验证，AI 不能指定任意目的路径。每次调用默认最长 180 秒，超时、服务离线、JSON 无效或分类不存在时保留源文件并记录错误。

## 处理范围

- 自动监控递归读取已设置的源目录，排除分类目标目录、隐藏目录、符号链接/目录联接、临时下载文件和 Office 锁文件。
- 文件尺寸和修改时间至少稳定 3 秒后分析；稳定窗口不能代替下载软件的完成信号。大型文件复制过程中仍会进行完整内容校验。
- TXT、Markdown、CSV、JSON 等文本，以及 PDF、DOCX 支持最多 12,000 字符摘录。大于 30MB 的文件只使用元数据；PDF最多取前6页。
- 图片、扫描 PDF、旧版 DOC/XLS/PPT、音视频和压缩包目前只按名称、扩展名和路径分类，没有 OCR 或视觉识别。
- 高置信度不等于正确，分类依据应明确，初次使用建议先审核。
- 文件变化会重新分类；已经归档的副本保留，新的版本同名时自动加编号。
- 标签存储于应用 SQLite 索引，不写入文件名、NTFS 或原文件内容。
- 每30秒扫描分类保存地址，将原有文件按所在分类索引到资料库；现有文件标签继承分类名称。
- 自动生成的目录保存在 `%LOCALAPPDATA%\FileAtlas\文件目录.md`，按逻辑分类展示已整理和原有索引文件。
- 为避免大目录影响界面流畅度，资料库每次展示最近 1,000 条匹配结果（可搜索缩小范围），目录树每个分类最多展示 200 个文件；Markdown 导出包含全部已归档和已索引文件。

## 文件保护与恢复

同名文件保留双方；使用排他创建，避免覆盖；复制后核验 SHA-256，再执行移动模式下的源文件删除。复制模式始终保留源文件。

撤销前校验目标内容；移动撤销遇到原路径占用会拒绝覆盖；复制撤销在源文件丢失或被修改时拒绝删除归档副本。撤销后同一版本不会被监控立即重新整理。

操作先写入日志再写文件。若进程意外退出，重启后未完成操作标记为 `recovery`，在整理记录中提示手动检查源和目标。跨文件系统移动与数据库写入不能形成一个原子事务，因此恢复项不会自动重试或删除文件。撤销期间突然断电也可能留下双方副本，需要手动核对。

应用数据、分类配置、标签与日志保存在 `%LOCALAPPDATA%\FileAtlas`。备份时请先从托盘退出，再复制整个数据目录。没有注册开机启动或 Windows 系统服务。

## 开发与验证

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/validate_worker.py
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/build.py
```

`scripts/validate_live.py` 使用独立临时样例验证真实 Claude 分类，不会读取个人文件。`app.py --data-dir <绝对路径>` 可指定独立应用数据目录，`--smoke` 用于启动后截图并退出。
